# Task 5.0 — Design-System Foundation

**Date:** 2026-10-18
**Status:** Implemented
**Priority:** P0. Phases 5.1–5.4 of the [UI redesign plan](../2026-10-18-ui-redesign-plan.md) build on it.
**Source:** [October 18 UI review](../reviews/2026-10-18-ui-review.md), Consistency and Accessibility sections.
**Builds on:** [EchoDriftCo/kite#9](https://github.com/EchoDriftCo/kite/pull/9) (light theme base, `--color-accent-text`, accent chip tokens).

---

## Overview

The review found the same few problems on almost every screen: orange and sage used as small text, placeholder grey used for real content, five competing button treatments, and browser `confirm()` pop-ups. This spec sets one rule for each, so later phases apply rules instead of making one-off fixes.

**In scope:** tokens, the Material palettes, button tiers, a shared confirm dialog, the type floor, and how recipe metadata is displayed.
**Not in scope:** page layouts (5.1 recipe page, 5.3 mobile), per-screen button placement (5.2), and the hard-coded colour sweep (5.4).

## 1. Colour roles

The brand colours stay the same. What changes is **where** each one may be used.

| Role | Token | Light | Dark | Use for | Never use for |
|---|---|---|---|---|---|
| Brand orange | `--color-primary` | `#ff8c42` | `#ff8c42` | Primary button fills, decorative icons, focus accents | Text, or small icons that carry meaning |
| Orange text | `--color-primary-text` **(new)** | `#a34b15` (5.9:1 on white, 4.9:1 on `surface-active`) | `#ffa366` (5.3:1 on slate-700) | Links, "Step 1", prices, orange labels | Fills |
| Rating stars | `--color-rating` **(new)** | `#d9691f` (≥3.2:1 on every light surface) | `#ffa366` | Filled stars (a graphic, so 3:1 applies) | Text |
| Sage | `--color-accent` | `#7c9885` | `#7c9885` | Borders, decorative icons, focus ring, chip tints | Text, or fills with text on them |
| Sage text | `--color-accent-text` (from #9) | `#4a6354` (6.6:1) | `#c1d4c7` (6.7:1) | **All links**, active nav, step numbers, accent buttons' labels | Fills |
| Sage fill | `--color-accent-fill` **(new)** | `#5a7363` | `#a8c4b2` | Selected toggles, filled accent buttons, the active scale button | Text |

**Material palettes** follow the same rule, so Material components pass without per-component overrides:

| Palette | Light default hue | Dark default hue |
|---|---|---|
| Primary (orange) | 500 `#ff8c42` with a dark label | 500 with a dark label |
| Accent (sage) | **700** `#5a7363` with a white label | **300** `#a8c4b2` with a dark label |
| Warn (red) | **700** `#d32f2f` with a white label (5.0:1) | **300** `#e57373` with a dark label (5.4:1) |

Text-only Material buttons (`mat-button` and `mat-stroked-button` with `color="primary"`) use `--color-primary-text` for their label, because the orange fill colour fails as text.

## 2. Button tiers

At most **one primary button per view**. Everything else steps down.

| Tier | Markup | Look | Use for |
|---|---|---|---|
| Primary | `mat-flat-button color="primary"` (`mat-raised-button` renders the same) | Orange fill, dark label, uppercase, **no shadow at rest**, 40px min height | The main action on the view: New Recipe, Start Cooking, Save, Sign In |
| Secondary | `mat-stroked-button` (no colour) | 1px `--color-border-default` outline, `--color-text-primary` label | Other actions that deserve a visible button: Edit, Grocery List, Cancel |
| Accent | `mat-flat-button color="accent"` | `--color-accent-fill` with `--color-on-accent` label | Rare. AI features (AI Generate), and only where it isn't competing with a primary |
| Tertiary | `mat-button` | Text only, `--color-text-primary` or `--color-accent-text` | Low-emphasis actions: Clear filters, Show more |
| Destructive | `mat-menu-item` with class `destructive` → confirm dialog | `--color-error-text` label and icon | Delete, Remove, Leave. **Never** a filled red button in a toolbar. |

A filled `color="warn"` button appears in one place only: the confirm button inside a destructive confirm dialog.

**Raised buttons:** the 66 existing `mat-raised-button` uses don't need a markup sweep. `theme.scss` removes their resting shadow so they render as flat. New code uses `mat-flat-button`.

## 3. Confirm dialog

`ConfirmDialogComponent` and `ConfirmService` replace every `window.confirm()` and `window.prompt()` call (15 call sites).

```ts
confirm.ask({
  title: 'Delete recipe?',
  message: '"Roasted Cherry Tomato Pasta" will be deleted. This can\'t be undone.',
  confirmText: 'Delete',
  destructive: true,          // red confirm button; Cancel gets focus first
  requireText?: 'DELETE',     // optional: type-to-confirm (account deletion)
}): Promise<boolean>
```

```
┌──────────────────────────────────────────┐
│ Delete recipe?                           │  ← h3 (--font-h3)
│                                          │
│ "Roasted Cherry Tomato Pasta" will be    │  ← body (--font-body-large, text-secondary)
│ deleted. This can't be undone.           │
│                                          │
│ [Type DELETE to confirm ____________]    │  ← only when requireText is set
│                                          │
│                     [CANCEL]  [DELETE]   │  ← Cancel = mat-button; Delete = flat warn
└──────────────────────────────────────────┘
```

- **Width:** 400px max, full width minus 32px on mobile. **Radius:** `--radius-xl`. **Padding:** `--space-lg`.
- **Focus:** opens on Cancel for destructive dialogs and on Confirm otherwise. Esc and backdrop click both mean Cancel.
- **Copy:** the title is a question naming the action ("Delete recipe?"). The confirm button repeats the verb ("Delete", never "OK"). The body says what is lost.
- **Async callers:** route guards (`unsavedChangesGuard`, recipe form `canDeactivate`) return the promise, which Angular accepts.

| Call site | Title | Confirm | Destructive |
|---|---|---|---|
| Recipe detail: delete | Delete recipe? | Delete | ✔ |
| Meal plan detail: delete | Delete meal plan? | Delete | ✔ |
| Circle detail: delete / leave / remove member | Delete circle? / Leave circle? / Remove member? | Delete / Leave / Remove | ✔ |
| Collection: delete | Delete collection? | Delete | ✔ |
| Dietary profile: delete | Delete profile? | Delete | ✔ |
| Cooking history: delete log | Delete cooking log? | Delete | ✔ |
| Recipe links: remove link | Remove link? | Remove | ✔ |
| Settings: remove samples | Remove sample recipes? | Remove | ✔ |
| Settings / app: sign out as guest | Sign out of guest session? | Sign out | ✔ |
| Settings: delete account | Delete your account? | Delete account | ✔ + `requireText: 'DELETE'` |
| Unsaved changes (guard, recipe form) | Leave without saving? | Leave | — |

## 4. Type floor

- Body text is never below **14px** (`--font-body`). `--font-caption` (12px) is allowed **only** for metadata attached to something else (timestamps, counts, badge labels).
- Every component rule below 12px, plus the 12px rules that hold sentences, moves to new size-only tokens (29 rules). `--font-size-caption` (12px) is for badges, counts and labels. `--font-size-body-small` (13px) is for helper sentences. Size-only tokens exist because many rules set weight or line-height separately, and the `font` shorthand would reset them.
- Recipe instructions use `--font-body-large` (16px / 24px).

## 5. Metadata vs chips

Chips look tappable, so only things that **are** tappable get them: tags and filters.

Recipe time, servings and visibility become one plain metadata line:

```
🕒 45 min    🍴 4 servings    ☰ 5 ingredients    🔢 4 steps
```

- Every item has a 16px icon; text is `--font-body-small` in `--color-text-secondary`. Items sit `--space-md` apart.
- No `·` separators: when the line wraps on narrow cards, a separator would start the next row. The icons keep items distinct.
- **Applies to:** recipe list cards, Discover cards, and the recipe page meta row (which keeps "Prep / Cook / Total" as separate items).

## Acceptance

1. `capture.mjs` (all 64 captures) writes **no** `contrast.txt` entries: no body text below 4.5:1 and no large text below 3:1, in either theme.
2. No `window.confirm(` or `prompt(` calls remain in `ui/src/app`.
3. No component SCSS rule uses `--color-primary` or `--color-accent` as a `color:` on text, or `--color-text-hint`/`--color-text-disabled` on readable text.
4. Before/after screenshots show no unintended layout changes.
5. `ng build --configuration production` passes, and the Karma specs added for `ConfirmService` pass.
6. `01-foundation.md` and `02-components.md` describe this system, not the old dark-only amber/teal one.
